# Draft Editing Plan

План на будущее: текстовые и голосовые правки после первого монтажа.

## Цель

После сборки первого `draft` пользователь должен иметь возможность вносить точечные правки:

- убрать паузу;
- чуть расширить сохраненный кусок;
- вырезать конкретную фразу или диапазон;
- оставить конкретную фразу;
- менять стиль сабов и связанные безопасные параметры;
- затем пересобрать `draft`, не прогоняя весь пайплайн заново с нуля.

## Почему это нужен отдельный слой

Нельзя безопасно править видео напрямую из свободного текста вроде:

- "тут поправь";
- "здесь расширь";
- "убери паузу вот там".

Нужен слой структурированных правок между `draft_ready` и `final render`.

## Что уже есть

- Экран `draft_ready` с заглушкой под правки в `app/components/ProjectCockpit.tsx`
- Базовый `voiceCommandProcessor` в `server/ai/voiceCommandProcessor.ts`
- Существующий `transcript`
- Существующий `EDL`
- Отдельный `draft render` и отдельный `final render`

## Чего не хватает

### 1. Сущность правки черновика

Нужна отдельная сущность, например `DraftEdit`, которая хранит:

- `projectId`
- `type`
- `source` (`text` | `voice`)
- `rawCommand`
- `resolvedInstructionJson`
- `status` (`pending` | `applied` | `rejected`)
- `message`
- `createdAt`

### 2. Якорь, к чему относится правка

Правка должна быть привязана к одному из якорей:

- диапазон времени;
- выбранный subtitle chunk;
- выбранный кусок transcript;
- текстовый якорь: `после слов ...`, `убери фразу ...`

Без якоря нельзя надежно менять EDL.

### 3. Парсер команды в structured intent

Текст или голос сначала должны превращаться в нормализованную команду.

Примеры целевых типов:

- `remove_pause`
- `keep_more_context`
- `cut_phrase`
- `keep_phrase`
- `change_subtitles_style`
- `rerender_from_here`

Пример:

`убери паузу после слов "и вот что важно"`

→

```json
{
  "type": "remove_pause",
  "anchorText": "и вот что важно",
  "direction": "after"
}
```

### 4. Resolver правки в таймкоды

Нужен отдельный backend-модуль, который:

- ищет якорь в нормализованном transcript;
- находит соответствующие слова/границы;
- переводит intent в точное изменение `keptRanges` / `removedRanges`;
- валидирует, что правка не ломает смысл и не создает опасный разрыв.

### 5. Пересборка draft без полного повторного pipeline

Нужен шаг вида:

- `applyDraftEdits(projectId)`

Он должен:

- читать `transcript`;
- читать текущий `EDL`;
- читать список `DraftEdit`;
- строить новый `EDL`;
- пересобирать `clean preview`.

### 6. История версий draft

Нужны версии:

- `draft v1`
- `draft v2`
- `draft v3`

Это позволит:

- откатывать неудачные правки;
- сравнивать варианты;
- не терять рабочий черновик.

## Рекомендуемый MVP

Сначала не делать полностью свободные голосовые команды.

Сначала сделать безопасную первую версию:

### UI

- текстовое поле правки;
- кликабельные subtitle chunks;
- кликабельный transcript;
- выбор якоря мышкой.

### Типы правок первой версии

- убрать паузу рядом с якорем;
- расширить сохраненный кусок на небольшой диапазон;
- вырезать выбранный диапазон;
- оставить выбранную фразу.

### Backend flow

- `POST /api/projects/{id}/edits`
- сохранить `DraftEdit`
- применить правку к текущему `EDL`
- пересобрать `clean preview`
- вернуть новый `draft`

## Голосовые правки

Голос не должен жить отдельной логикой.

Правильный путь:

- голос → транскрипция;
- транскрипция → structured instruction;
- structured instruction → тот же backend flow, что и у текстовых правок.

То есть text и voice должны сходиться в один и тот же формат команд.

## Порядок реализации

1. Добавить модель `DraftEdit`
2. Добавить API для сохранения правок
3. Сделать UI выбора якоря по transcript/subtitles
4. Реализовать первые 3–4 безопасных типа правок
5. Добавить пересборку `draft` без полного reprocess
6. Добавить историю версий
7. После этого подключить голосовые команды к той же схеме

## Главное ограничение

Нельзя строить систему на расплывчатых командах без указания, где именно менять видео.

Сначала нужен надежный edit model с якорями и versioning.
Потом уже удобные способы ввода: текст, голос, быстрые кнопки.
