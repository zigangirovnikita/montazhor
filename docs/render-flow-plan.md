# Render Flow Plan

Новый целевой пользовательский флоу для продукта.

Цель: разделить три разных слоя, которые сейчас смешаны:

- монтаж речи;
- визуальное оформление;
- финальный экспорт.

Это должно сделать UX понятнее и подготовить систему к правкам после черновика.

## Главный Принцип

Пользователь не должен на старте выбирать технический пайплайн.

Сначала он решает, как чистить речь.
Потом смотрит черновой монтаж.
Потом выбирает, как оформить итоговое видео.
Потом вносит правки.
И только после этого подтверждает финальную подготовку к скачиванию.

## Новый Пользовательский Флоу

### 1. Upload

Пользователь просто загружает видео.

На этом экране не должно быть выбора:

- субтитров;
- инфографики;
- шрифтов;
- визуального режима.

## 2. Cleanup Mode

После загрузки пользователь выбирает способ чистки исходной речи.

Стартовые варианты:

1. `Только убрать паузы`
2. `Убрать паузы и почистить по смыслу`

Это влияет только на:

- transcript;
- EDL;
- clean cut;
- content selection.

Это не должно влиять на оформление.

## 3. Draft Analysis

После выбора cleanup mode система делает:

- транскрипцию;
- анализ речи;
- построение EDL;
- сборку clean draft video.

На этом этапе не должны применяться:

- субтитры;
- инфографика;
- CTA;
- картинки/вставки;
- финальные visual presets.

Результат этапа:

- `draft clean video`;
- transcript;
- EDL;
- logs.

## 4. Presentation Mode

После готовности clean draft пользователь выбирает, как оформить видео.

Стартовые варианты:

1. `Только субтитры`
2. `Субтитры + инфографика`
3. `Субтитры + инфографика + картинки/видео`

Это уже отдельный слой, который не должен заново пересобирать анализ речи.

## 5. Style Configuration

После выбора presentation mode пользователь попадает на экран визуальных настроек.

Здесь UI должен быть карточками и пресетами, а не редактором с десятками полей.

Что можно настраивать:

- preset субтитров;
- шрифт;
- цвет;
- стиль подложки;
- активное слово: `вкл/выкл`;
- размер: `спокойный / крупный / акцентный`;
- положение: `ниже / выше / авто`;
- стиль инфографики;
- подложка инфографики: `чистая / прозрачная / цветная`;
- анимации: `выкл / спокойно / активно`.

Важно:

- лучше 5–8 понятных визуальных пресетов;
- и только 2–4 дополнительных тумблера;
- не превращать это в ручной редактор.

## 6. Styled Preview Render

После выбора оформления система собирает предфинальную review-версию.

Она уже должна содержать:

- субтитры;
- split-layout, если нужен;
- инфографику;
- дополнительные картинки/вставки, если режим это предполагает.

Это основная preview-версия, которую пользователь смотрит и правит.

## 7. Review And Corrections

На этом экране пользователь получает:

- preview video;
- transcript/subtitle anchors;
- кнопки быстрых правок;
- текстовое поле;
- позже голосовые правки.

Примеры правок:

- `убери паузу здесь`;
- `оставь больше контекста`;
- `сделай субтитры меньше`;
- `сделай инфографику спокойнее`;
- `убери этот кусок`;
- `выделяй текущее слово`.

Именно этот экран должен стать базой для будущей системы `DraftEdit`.

## 8. Confirm For Download

Когда preview пользователя устраивает, он нажимает:

- `Подготовить к скачиванию`

Это отдельный confirm-step.

Пользователь не должен получать кнопку скачать раньше, чем подтвердил review-версию.

## 9. Final Export

После подтверждения система делает финальную сборку:

- final export;
- cleanup ненужных временных файлов;
- показ итогового видео;
- кнопка `Скачать`.

## Экранная Структура

Предлагаемый порядок экранов:

1. `Загрузка`
2. `Как почистить видео`
3. `Черновой монтаж готов`
4. `Как оформить видео`
5. `Выбор стиля`
6. `Предпросмотр`
7. `Внести правки`
8. `Подготовить к скачиванию`
9. `Скачать итоговое видео`

## Что Это Меняет В Архитектуре

Текущий flow должен быть разрезан на три независимые фазы:

1. `analysis`
2. `styled preview render`
3. `final export`

### Analysis

Включает:

- upload ingest;
- audio extraction;
- transcription;
- VAD / diarization;
- script selection;
- EDL planning;
- clean draft render.

### Styled Preview Render

Включает:

- subtitles;
- infographic mode;
- motion overlays;
- image/video inserts;
- style preset application.

### Final Export

Включает:

- подтвержденную review-версию;
- финальный encode;
- cleanup;
- download-ready asset.

## Что Нужно Хранить Отдельно

В проекте нужно развести разные типы пользовательского выбора:

- `cleanupMode`
- `presentationMode`
- `stylePreset`
- `styleOptionsJson`
- `draftPreviewPath`
- `reviewReadyPath`
- `finalVideoPath`

Нельзя смешивать cleanup mode и presentation mode в одном поле `editMode`.

`editMode` можно оставить временно для совместимости, но целевой путь — разнести эти вещи.

## Рекомендуемые Prisma-Поля

Минимальный целевой набор:

- `cleanupMode`
- `presentationMode`
- `stylePreset`
- `styleOptionsJson`
- `draftVersion`
- `reviewVideoPath`
- `finalVideoPath`

Позже:

- `reviewStatus`
- `lastConfirmedDraftVersion`

## Рекомендуемые Статусы Проекта

Текущие статусы стоит эволюционировать к более понятным фазам:

- `uploaded`
- `analyzing`
- `draft_ready`
- `configuring_style`
- `rendering_preview`
- `review_ready`
- `applying_edits`
- `rendering_final`
- `done`
- `error`

## UX Ограничения

Не превращать продукт в сложный редактор.

Не делать:

- свободный manual timeline;
- десятки ручных параметров;
- пиксельное позиционирование;
- огромный набор low-level controls.

Делать:

- ограниченный набор пресетов;
- понятные карточки;
- preview before final export;
- постправки после preview.

## MVP Sequencing

Реализацию лучше делать по этапам.

### Phase 1

- разнести cleanup mode и presentation mode;
- оставить фиксированные style presets;
- добавить preview перед final export.

### Phase 2

- добавить экран style configuration;
- ввести `styleOptionsJson`;
- добавить карточки выбора шрифта/подачи/инфографики.

### Phase 3

- подключить post-draft corrections;
- отдельный review loop;
- подтверждение перед final export.

## Главное Решение

Продуктовый pipeline должен быть таким:

`upload -> cleanup decision -> analysis draft -> presentation decision -> style config -> preview -> corrections -> confirm -> final export -> download`

Это целевой флоу, вокруг которого дальше стоит перестраивать UI, статусы и backend pipeline.
